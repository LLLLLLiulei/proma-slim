## MODIFIED Requirements

### Requirement: 已选区块必须仅作为下一条消息的隐藏上下文参与发送
系统 SHALL 将当前已选区块仅作为下一条用户消息的隐藏上下文参与发送；当同一轮还存在已确认的 CMS 数据源选择结果时，系统 SHALL 将区块 `selector` 与归一化后的 CMS 选择结果共同作为隐藏上下文注入，而不改写用户在消息列表中可见的正文内容。

#### Scenario: 发送消息时注入选中区块的隐藏上下文
- **WHEN** 用户已选中某个页面区块并发送下一条消息，且当前没有额外的 CMS 数据源选择结果
- **THEN** 系统 SHALL 将该区块的 `selector` 与该条用户消息一起作为隐藏上下文发送给 Agent
- **AND** 系统 SHALL 保持消息列表中用户可见正文仍为用户原始输入文本

#### Scenario: 同一条消息可同时注入区块与 CMS 数据源上下文
- **WHEN** 用户已选中某个页面区块，且当前消息还携带了已确认的 CMS 数据源选择结果
- **THEN** 系统 SHALL 将区块 `selector`、归一化后的 CMS 数据源结果与该条用户消息一起作为隐藏上下文发送给 Agent
- **AND** 系统 SHALL 继续保持消息列表中用户可见正文仍为用户原始输入文本

#### Scenario: 隐藏上下文不包含未确认的大块页面或 CMS 原始负载
- **WHEN** 系统为带选区和可选 CMS 选择结果的消息准备发送上下文
- **THEN** 系统 SHALL 不额外注入完整 HTML 片段、截图、原始 CMS API 响应、服务账号凭证或未被用户确认的原始受保护资源地址

#### Scenario: 发送成功后自动清除当前瞬时选择上下文
- **WHEN** 一条带有已选区块上下文且可选带有 CMS 数据源上下文的消息发送成功
- **THEN** 系统 SHALL 清除当前页面区块选择状态与高亮
- **AND** 系统 SHALL 清除仅供当前消息使用的 CMS 选择结果，使其不再继续作用于后续下一条以上的消息

#### Scenario: 发送失败时保留当前瞬时选择上下文以便重试
- **WHEN** 一条带有已选区块上下文且可选带有 CMS 数据源上下文的消息发送失败
- **THEN** 系统 SHALL 保留当前已选区块及其高亮状态
- **AND** 系统 SHALL 保留当前消息对应的 CMS 选择结果
- **AND** 系统 SHALL 允许用户在不重新选区或重新选 CMS 的情况下重试发送
