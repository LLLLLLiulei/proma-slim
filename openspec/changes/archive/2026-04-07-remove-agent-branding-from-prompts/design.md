## Context

当前助手的模型可见提示表面分散在三处：运行时 `systemPrompt.append`、动态上下文注入，以及新建 page-builder 工作区时写入的根级 `CLAUDE.md` 模板。这些文本里仍存在品牌名和底层实现身份表述，导致助手在对外交流时可能沿用这些身份，而不是仅以职责身份和用户互动。

这次调整是一次跨越运行时 prompt builder 与工作区模板的收敛。目标不是重写整个 Claude Agent SDK 默认行为，而是把对外身份相关的可见文本统一改成“职责身份 + 中性宿主措辞”，从而降低品牌/底层身份泄漏到用户对话中的概率。

## Goals / Non-Goals

**Goals:**
- 让助手在正常用户对话中只以职责身份交流，不自称具体产品、模型、CLI、SDK、厂商服务或内部代号。
- 收敛运行时系统提示词、动态上下文和 page-builder `CLAUDE.md` 模板中的品牌化措辞。
- 保持现有 `claude_code` preset 与 scratch/repo guardrail、权限策略、workspace 语义等既有运行时能力不变。
- 为新建工作区提供中性模板，同时不破坏已有工作区中用户可能手改过的 `CLAUDE.md`。

**Non-Goals:**
- 不整体替换 Claude Agent SDK 的 `claude_code` preset。
- 不清理仓库内所有非 prompt 场景下的品牌文案，例如登录错误、调试日志、内部类型名或实现注释。
- 不主动覆盖已存在的工作区根级 `CLAUDE.md`。

## Decisions

### 1. 保留 `claude_code` preset，只强化追加身份约束

运行时继续使用 SDK 的 `preset: 'claude_code'`，在 `append` 中增加更强的身份约束与中性表述，而不是直接切换为全自定义 system prompt。

选择原因：
- 可以保留现有稳定的默认行为与工具语义。
- 本次需求聚焦于“不要自称某个品牌/底层身份”，不需要承担整体替换 preset 带来的行为回归风险。

备选方案：
- 全量自定义 system prompt：控制力更强，但需要自行补回更多默认行为约束，回归风险更高。

### 2. 将“身份约束”和“宿主措辞”一起收敛到运行时 prompt builder

`agent-prompt-builder` 中的身份段、工作区语义段、scratch runtime 说明和回复约束统一改为中性表述，避免模型可见文本里继续出现品牌化自我描述。

选择原因：
- 这部分内容会在每轮运行时注入，对已有工作区也能立即生效。
- 可以直接覆盖当前最容易影响回复口径的提示表面。

备选方案：
- 只改 `CLAUDE.md` 模板：只能影响新工作区，对现有工作区见效慢，且无法兜住运行时品牌措辞。

### 3. 更新 page-builder 模板文本，但不迁移已有 `CLAUDE.md`

同时更新英文和中文模板内容，使新工作区从初始化起就使用中性模板；对于已经存在根级 `CLAUDE.md` 的工作区，继续维持“不覆盖”的现有策略。

选择原因：
- 能保证未来创建的工作区不再继续注入品牌化描述。
- 不覆盖已有文件可避免误伤用户手改内容和其他局部工作区定制。

备选方案：
- 启动时批量重写已有工作区 `CLAUDE.md`：可以更彻底，但风险是覆盖用户已有编辑，且与当前模板初始化契约冲突。

### 4. 用测试锁定“模型可见文本不再鼓励品牌自称”

新增或调整测试，覆盖运行时 prompt append、动态上下文和模板初始化结果，确保这些模型可见文本不再包含当前关注的品牌化自我描述。

选择原因：
- 这类问题容易被后续文案调整重新带回，需要用断言固定。

备选方案：
- 仅靠人工 review：成本低，但回归风险高。

## Risks / Trade-offs

- [已有工作区的根级 `CLAUDE.md` 可能仍保留旧文案] → 通过更强的运行时系统提示词兜底，并保留“不覆盖已有模板”的安全边界。
- [保留 `claude_code` preset 仍可能在极少数场景残留底层身份倾向] → 在 `append` 中增加更明确的否定性约束；若后续仍有残留，再单独评估是否整体替换 preset。
- [仓库其他非 prompt 文案仍含品牌或底层服务名] → 明确列为本次非目标，后续如需统一产品文案，再单开 change 处理。

## Migration Plan

1. 更新运行时 prompt builder 中的身份、工作区语义和回复约束表述。
2. 更新 page-builder 的英文和中文 `CLAUDE.md` 模板文本。
3. 补充或调整相关测试，确认模型可见表面已中性化。
4. 不改写已有工作区的根级 `CLAUDE.md`；若需要让存量工作区也迁移模板，后续单独设计安全迁移流程。

回滚策略：
- 若新文案导致回复质量回退，可直接回滚本次 prompt/template 文本修改，而无需做数据迁移。

## Open Questions

- 是否需要在后续单独收口 UI 友好报错、状态提示等非 prompt 文案中的 `Claude Code` 字样；本次先不纳入范围。
