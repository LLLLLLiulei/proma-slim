## Why

Proma 目前主要提供面向通用 Agent 工作流的对话式工作台，但还没有一个面向“用自然语言生成网页”的产品化入口。现在需要新增一个专门的 `page-builder` 应用，用现有工作区、会话和对话能力快速验证“AI 构建网页”这个场景，而不是再重建一套独立的聊天和运行时系统。

## What Changes

- 新增 `apps/page-builder` 应用，提供面向 AI 建网页场景的独立首页和构建页。
- 在首页提供极简需求输入入口，用户提交后真实创建一个名为“未命名项目”的工作区和首个会话，并直接进入构建页。
- 在构建页提供紧凑的双栏工作台：左侧为网页预览 iframe 面板，右侧复用现有 Agent 对话框、消息列表和流式会话能力。
- 在构建页顶部增加“项目名”展示与编辑能力，语义上对应工作区名称，而不是现有会话标题。
- 复用 `apps/app` 现有的工作区、会话、SSE、消息渲染和输入能力，只为 `page-builder` 增加必要的启动封装、页面布局和项目级 UI。
- 增加一次性初始化发送流程，使首页输入的需求在进入构建页后自动作为首条消息发送，同时避免刷新或重复进入时重复发送。

## Capabilities

### New Capabilities
- `page-builder-app`: 提供专用于自然语言生成网页的独立应用体验，包括首页启动流、项目初始化和紧凑型构建工作台。

### Modified Capabilities
- None.

## Impact

- 新增 `apps/page-builder` 前端应用及其页面、布局和启动逻辑。
- 影响 `apps/app` 中部分现有前端能力的复用方式，可能需要为现有 Agent 对话视图增加嵌入 `page-builder` 时所需的最小可配置能力。
- 继续复用现有工作区、会话、消息流和后端 HTTP 接口，不引入新的核心后端协议。
- 需要调整新应用的构建与样式配置，以支持直接复用 `apps/app` 内部前端模块。
